# GLASS AGENT — AI-маркетолог на базе ChatGPT Plus без платного OpenAI API

Ты — Senior Python Developer, AI Engineer и Software Architect.

Разработай Backend для проекта **Glass Agent** — автономной мультиарендной маркетинговой платформы.

## КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ

Для работы языковой модели разрешено использовать **только существующий аккаунт ChatGPT Plus**.

СТРОГО ЗАПРЕЩЕНО:

- Использовать обычные OpenAI API-ключи.
- Требовать `OPENAI_API_KEY`.
- Использовать отдельный платный OpenAI API billing.
- Незаметно переключаться на платный API.
- Использовать cookie ChatGPT, неофициальные endpoints или браузерную автоматизацию для обхода авторизации.
- Выдавать mock-ответы за ответы ChatGPT.

**Основной способ подключения: официальный Sign in with ChatGPT с OAuth и разрешением на использование подписки Plus.**

Допускаются официальные inference-запросы, авторизованные OAuth-токеном ChatGPT Plus, если это разрешено для конкретного способа размещения приложения.

Это не разрешение использовать обычный платный OpenAI API.

Если поддерживаемая OAuth-интеграция недоступна, честно сообщи о техническом ограничении. Не создавай неофициальную интеграцию.

## 4. Отдельный AI-чат для каждой компании

Это одно из главных требований.

Каждая компания имеет собственный постоянный разговор с AI.

Пример:

```text
Company 1 — Салаватстекло
    conversation_id: UUID_A
    memories: A
    RAG: A
    history: A

Company 2 — Другая компания
    conversation_id: UUID_B
    memories: B
    RAG: B
    history: B
```

Все диалоги создаются и управляются нашим Backend.

Не пытайся создавать настоящие чаты внутри пользовательского интерфейса ChatGPT.

Для каждого запроса:

1. Получить компанию из авторизованного контекста.
2. Найти её conversation.
3. Загрузить последние сообщения.
4. Загрузить долговременную память.
5. Получить релевантную информацию через RAG.
6. Сформировать контекст модели.
7. Вызвать ChatGPT Plus через разрешённую интеграцию.
8. Сохранить ответ в PostgreSQL.
9. Обновить память.

Не рассчитывай на автоматическое сохранение истории на стороне ChatGPT Plus.

Используй PostgreSQL как основной источник истории.

## 5. Долговременная память

Реализуй четыре типа памяти.

**Short-Term Memory**

Последние сообщения и текущая задача.

**Long-Term Memory**

Стиль бренда, маркетинговые цели, предпочтения, ограничения и подтверждённые решения.

**Episodic Memory**

История выполненных действий: созданные посты, согласования, публикации и результаты.

**Conversation Summaries**

Краткие сводки старых диалогов для экономии контекста.

История не должна исчезать после перезапуска сервера.

При большом количестве сообщений автоматически формируй сводки, но сохраняй оригинальную историю.
