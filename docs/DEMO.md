# Демонстрация обязательного сценария (п. 6 ТЗ)

Подготовка: `chatgpt_login` выполнен, `scripts.bot` и `scripts.scheduler` запущены, у компании задан
тестовый канал (`/setchannel telegram @test_channel`, бот — админ канала), представитель — `owner`.
Без ChatGPT сценарий можно показать на ТЕСТОВОЙ модели (`AI_PROVIDER=mock_dev`) — ответы будут помечены.

| Шаг ТЗ | Действие | Что видно |
|---|---|---|
| 1. Профиль и сведения о компании | админ: `/newcompany Тест`, `/addsource website …`, загрузка PDF, `/sync` | источники `ok`, `manage list` |
| 2. Задача через Telegram | клиент: «Подготовь пост про энергосберегающее стекло для фасадов» | бот печатает… |
| 3. Анализ с учётом компании | агент вызывает `search_company_knowledge` | `meta.steps` в истории |
| 4. Публикация с текстом и изображением | `create_post_draft` + `prepare_post_image` | черновик с картинкой |
| 5. На согласование | `submit_for_approval` | согласующему: материал, площадка, время, кнопки |
| 6. Утвердить или изменения | «✏️ На доработку» → «добавь про шумоизоляцию» → AI переписывает → «🚀 Согласовать и опубликовать» | новая ревизия |
| 7. Публикация в тестовом канале | планировщик (≤30 с) | пост в канале |
| 8. AI сообщает результат | уведомление со ссылкой на пост | «✅ Опубликован …» |
| 9. Уточняющий вопрос | «А сколько просмотров у того поста?» | агент берёт пост из памяти, `get_post_analytics` |
| Задача по расписанию | `manage run-task <slug> report` или дождаться расписания | отчёт приходит без запроса |

Проверка разделения компаний: второй компанией (`/newcompany`) спросить о фактах первой — агент их не видит;
в Mini App/API чужая компания → 404.

Проверка «не публикует без разрешения»: нажать «❌ Отклонить» — пост остаётся `rejected`, планировщик его не трогает.
